## 审核要点
1. 结构齐全性：报告是否恰好包含 D1~D7 七个维度，每维一行「维度：评分+评语」，且末行有「综合评级：X」？缺少任一维或综合评级 → FAIL: 指出缺哪项。
2. 评分合法：每个维度的评分与综合评级取值是否仅限 S/A/B/C/D 五个字符？出现 S+/A-、数字分、中文（优/良）等其他写法 → FAIL: 指出哪一维。
3. 基于事实、无虚构：抽取评语中的关键锚点（章节号、人物名、字数具体数值、伏笔编号如 G-Vxxx、CV/变异系数等），核对是否能在 {user_prompt} 注入的梗概与图谱事实中找到依据。发现编造的章节号、不存在的人物、虚构的字数、夸大的回收率或 CV 值 → FAIL: 指出具体虚构点。
4. 引用图谱/梗概事实：每维评语是否带有可追溯的事实锚点，而非空泛套话（如仅写「结构良好」「情节一般」而无任何数据/章节/人物支撑）？若某维评语完全无事实锚点 → FAIL: 指出哪一维缺事实。
5. 综合评级一致性：综合评级是否为七维评分合乎逻辑的加权总体（例如多数为 C/D 却给 S 属明显逻辑矛盾）→ 明显矛盾 → FAIL: 指出矛盾处。

请按以下格式输出（严格遵守）：
第一行必须是且仅是判定词：PASS 或 FAIL（不得加任何前缀，直接写 PASS 或 FAIL，不要写"通过/不通过"作为判定词）。
第二行起可附逐项核对：
- 结构齐全性：通过 / 未通过（缺哪项）
- 评分合法：通过 / 未通过（哪一维）
- 基于事实无虚构：通过 / 未通过（具体虚构点）
- 引用事实锚点：通过 / 未通过（哪一维）
- 综合评级一致性：通过 / 未通过（矛盾处）

注意：
- 若以上五项全部通过，第一行必须写 PASS，严禁写 FAIL（即使你对某项做了分析，结论也只能是 PASS）。
- 仅当某一项确实存在真实违反时，第一行才写 FAIL，并只列出真正未通过的项（已通过的项不要列作问题）。
