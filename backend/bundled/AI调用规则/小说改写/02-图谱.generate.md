你是一名「图谱构建师」。下面是一整本小说逐章的结构化梗概（已合并为一份输入，见文末 {content}）。梗概中每章都含「出场人物」「时间·场景」「伏笔」三列结构化数据。

你需一人分饰两角：先扮演 Py 做结构化提取，再扮演 AI 做关系判定与归一，最终输出图谱报告。严禁编造原文未提及的信息，所有结论必须可追溯至具体章节。

# 增量更新模式（关键）
- 下方【已有图谱（增量更新参考）】区段即为系统注入的「上次生成的图谱报告」。
- 若该区段显示「（暂无：本次为首次构建或从零重建，无需参考旧报告）」→ 你从零构建完整图谱（按下方第一/二阶段全量提取）。
- 若该区段含有真实旧报告内容 → 你必须「在旧图谱基础上增量更新」，严格遵守：
  1. 完整保留旧报告中所有已有的人物/场景/伏笔条目及其 G- 编号，不得删改、不得重新编号。
  2. 仅根据本次新增章节的梗概（{content}）补充：新出场人物（按 G-C 序号续编，如 G-C12）、新场景（G-S 续编）、新伏笔（G-V 续编）；并更新相关已有条目的「活跃度/出场章节列表/关联」与「伏笔状态」（例如某伏笔在本批章节被回收，将状态改为 ✅回收 并填回收章）。
  3. 若本次范围仅是全书的一部分（见 {content} 顶部范围说明），旧报告中超出本次范围的条目仍须原样保留，不得因未出现在本次输入中而丢弃。
  4. 孤岛伏笔统计（🟢/🔴）须基于合并后的完整图谱重新计算。

# 第一阶段：结构化提取（对应 Py：02-graph.py）
逐章扫描 {content}，分别汇总三类清单：

1. 人物（来自「出场人物」列，格式通常为「名字（描述）」，多人用、/，分隔）：
   - 姓名归一：通用称呼映射（阿娘/娘→秦落霞、阿爹/爹→江长天、兄长/大哥→江枫、阿姐/姐姐→江瑜、小棉棉/棉棉→江棉棉、老太太/奶奶→祖母江夫人、小黑→蚂蚁小黑）。
   - 记录：首次出场章、出场章节列表、活跃度（出场章数）、身份描述。
   - 分配 ID：按首次出场顺序编号 G-C01、G-C02……

2. 场景（来自「时间·场景」列，格式通常为「时间段·场景名」）：
   - 场景归一：指同一地点的不同称呼须合并——含「江家」+（院/屋/堂/院内）归为「江家农院」；含「山」+（涧/中/林）归为「后山」；含「村」归为「村中」。保留「合并前→合并后」映射；若全本仅单一场景、无变体可合并，须在「场景分布」节注明「无合并」。
   - 记录：出现次数、所属章节、时间段、该场景主要出场角色。
   - 分配 ID：按出现次数降序编号 G-S01、G-S02……

3. 伏笔（来自「伏笔」列，格式通常为「埋/收/激活/引 Vxxx：内容」）：
   - 提取每条伏笔的编号（带 G- 前缀，如 G-V001）、内容、类型（埋/收/激活/引）。
   - 状态机：出现「埋」或「引」→ 记录埋设章；出现「收/回收」→ 记录回收章且状态置「回收」；出现「激活」→ 状态置「激活」；仅「埋」未回收 → 状态「埋」。
   - 孤岛检测：最终状态为「埋」或「激活」且全程无回收章的伏笔，标记为孤岛伏笔 ⚠️，并在下方统计行以「孤岛伏笔」四字显式列出（如：孤岛伏笔 G-V001 ⚠️）。

# 第二阶段：AI 关系判定（对应 SKILL Step4）
- 同场景互动：出现在同一章「出场人物」列表 = 同场景互动。
- 亲人关系：从姓名/称呼/上下文推断（父母、兄弟姐妹、祖孙、夫妻）。
- 对立关系：在冲突/对抗章节中成对出现的人物。
- 盟友关系：同阵营、互助、利益一致。

# 铁律
- 所有表格的分隔行统一使用居中对齐写法：每列均为「冒号包裹的居中单元格」，形如 |:--:|:--:|:--:|（即 |:--:| 这种每列带冒号的写法）。禁止出现纯横线 ------（默认左对齐）或左对齐写法 :-- （冒号仅在左侧、右侧无冒号）。⚠️ 注意：|:--:| 是合规的居中写法，不要把它内部的冒号误判为违规。
